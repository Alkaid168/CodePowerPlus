# 后续对话交接说明

## 使用方式

开始任何前端 UI 工作前，按顺序阅读：

1. `docs/design/FINAL_FRONTEND_TEMPLATE.md`（权威基线，优先级最高）
2. `docs/design/tokens.json`
3. `docs/design/foundations.md`
4. `docs/design/components.md`
5. `docs/design/motion.md`
6. `docs/design/README.md`（补充与历史记录）

如果任务只涉及页面布局，也必须先继承上述组件规则，禁止重新定义颜色、圆角、边框、阴影和动效。

## 设计基线

- 名称：CodePowerPlus 桌面工作台 UI。
- 方向：明亮、克制、黑白灰主色，借鉴 macOS 与 Xept 的精密边界。
- 页面形态：浏览器内全屏工作台，不是原生窗口。
- 组件状态：已确认。
- 页面布局：总览与知识树已实现；其他页面尚未逐个设计。
- 总览页已经在 `app/static/js/views/overview.js` 与 `app/static/css/overview.css` 按方案 A 实现。
- 知识树已经在 `app/static/js/views/knowledge.js` 与 `app/static/css/knowledge.css` 实现。
- 其余页面仍沿用旧布局结构，但已继承新的黑白灰 token；后续逐个重做时不要以旧布局作为视觉依据。

## 实现优先级

1. 先落 token：颜色、字体、间距、圆角、阴影、动效。
2. 再实现基础控件：按钮、输入、选择、反馈。
3. 然后实现数据组件：表格、列表、知识树、状态。
4. 最后实现弹层和组合组件。
5. 页面布局必须在用户明确要求后单独设计。

## 禁止项

- 禁止 `linear-gradient` 和 `radial-gradient`。
- 禁止紫色品牌色、蓝色光晕和玻璃高光。
- 禁止把所有卡片做成胶囊或超大圆角。
- 禁止大面积黑色卡片、黑色 Hero 或整块高对比黑底；黑色只用于文字、边界、选中态和小面积反色按钮。
- 禁止可编辑输入框使用灰底。
- 默认输入框使用灰色边框；只有真实聚焦、正在输入时才改成黑色。
- 静态截图或设计板不得使用常驻 `.focus` 造成黑色默认边框。
- 禁止输入框聚焦时同时出现边框、outline 和 box-shadow。
- 禁止结果标签使用固定宽度导致文字偏移。
- 禁止知识树只给文字加短背景；必须使用整行长条。
- 禁止知识树依赖字体箭头；使用 CSS 绘制。
- 禁止用 `transition: all`。
- 禁止对每天 100+ 次的键盘动作做开合动画。

## 给另一个对话的推荐开场

> 只负责实现 CodePowerPlus 的桌面端前端 UI。先完整阅读 `docs/design/FINAL_FRONTEND_TEMPLATE.md`，再读取 `tokens.json`、`foundations.md`、`components.md` 和 `motion.md`。以最终模板为权威基线，严格复用已确认的工作台外壳、黑、白、灰 token、XEPT 式圆角、白色卡片、黑色 Primary 按钮、灰色 Secondary 按钮和动效规范。不要恢复黑色主卡、主卡右侧灰色小卡、Logo 或旧顶部栏。默认只实现样式，不实现业务逻辑。

## 已确认的关键产品语义

- 知识体系是题目标签词表，展示层级和叶子介绍。
- 模型分析与人工审核必须视觉上可区分。
- 只有已审核且版本一致的分析才能成为学习证据。
- AC、WA、TLE、CE 是判题状态，不是装饰标签。
- 推荐、画像、学习路径和代码辅导属于学习者工作区。
- 题目分析、审核队列属于研究工作区，但整体保持统一工作台。

## 交接验收

后续实现完成后至少检查：

- 视觉是否与 `reference/` 截图保持同一价值判断。
- 所有可编辑控件是否为白底。
- 聚焦是否只有一层黑色边框。
- 所有状态标签是否居中、宽度自然、右边界统一。
- 知识树是否为整行长条，箭头位置和字体是否稳定。
- 是否存在渐变、彩色 glow、超大圆角或 `transition: all`。
- 键盘焦点、禁用态、减少动态是否完整。






## 最新全局规则（2026-09-14）

- LOGO：使用 `app/static/assets/codepowerplus-mark.png`，由根目录 `LOGO.png` 去除白底后透明裁切。
- 品牌文字：仅 `CodePowerPlus`，字体尚未最终确定；不要擅自换成中文品牌名。
- 侧栏：仅关键功能入口，无分组标题，无学习者/版本/模型状态页脚。
- 无顶部栏。页面标题直接位于主体首行；只有主体区域滚动。
- 主体使用白色气泡卡片并铺满主体；无顶部栏，侧栏宽度 260px、文字黑色、条目高度 44px。禁止大面积黑色卡面。
- 动效：所有卡片进入页面时播放 `card-enter`；减少动态时改为短透明度过渡。
- 信息密度：移除重复解释小字，指标卡只保留标题和值。
- 阶段边界：只实现样式与视觉结构，不新增业务逻辑。

### 总览极简结构

- 顶部问候 + 两个操作。
- 三张指标卡。
- 一张当前建议卡。
- 一张薄弱知识点卡。
- 不再增加常用入口、流程状态或系统状态卡。

### 总览双状态

- 无题目：中间卡片显示“建立第一道题的学习记录”，主按钮为“录入并分析题目”。
- 有题目：中间卡片调用现有题目列表，显示第一道题的标题和来源，提供“开始练习 / 查看题目分析”。
- 两种状态都保持三张指标卡、一个主建议卡和一个薄弱知识点卡。
