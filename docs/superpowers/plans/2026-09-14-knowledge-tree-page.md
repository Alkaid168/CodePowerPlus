# 知识树页面实施计划

日期：2026-09-14
状态：已实现并通过浏览器验收（2026-09-14）
权威参考：`docs/design/FINAL_FRONTEND_TEMPLATE.md`（§2 工作台外壳、§4 字体圆角、§5 知识树组件、§6 动效）。与其历史说明冲突时，以该文件为准。

## 1. 目标

把「知识树」页做成**标签词表的正式浏览与检索工具**。完成的标志是：任何人打开这一页，都能在十秒内回答三件事。

1. 这个系统一共把程序设计知识分成了哪些领域、每个领域下面有什么。
2. 某个具体知识点挂在哪条路径上，它是什么。
3. 哪些节点可以当题目标签，哪些只是统计用的领域。

这一页不负责推荐、不负责做题，也不改标签内容。标签词表本身在 `data/knowledge_taxonomy.json`。

## 2. 现状核对（2026-09-14 实测）

### 2.1 后端：够用，本轮不需要新增接口

| 能力 | 接口 | 实测 |
| --- | --- | --- |
| 全树（含介绍、下级） | `GET /api/knowledge/tree` | 返回 133 KB，382 节点 |
| 关键词 + 层级搜索 | `GET /api/knowledge/search?q=&level=` | `q=最短路` 命中 2 条：`graph.shortest-path`、`graph.mod-shortest-path` |
| 单点详情（祖先路径 + 下级） | `GET /api/knowledge/{id}` | 返回 ancestors / children |

数据实况：版本 `2026.09.7`，382 节点 = 9 L1 + 170 L2 + 203 L3；叶子知识点 342 个（203 个 L3 + 139 个没有下级的 L2），每个叶子都带 75–162 字介绍。

结论：**知识树页是纯前端任务**。搜索结果的祖先路径可以由前端从已缓存的全树计算，不需要后端配合。

### 2.2 前端：页面存在，但不是模板的样子

现有实现是 `app/static/js/views/knowledge.js` 加 `app/static/css/components.css` 里的 `.tree*` 规则，用的是通用卡片布局，与模板 §5 的知识树组件规范有明确差距。

## 3. 差距清单

| 编号 | 现状 | 模板要求 |
| --- | --- | --- |
| G1 | 树节点是包住文字的小按钮 | 整行长条，宽度撑满容器 |
| G2 | 没有右侧等级框 | 固定 38px 等级框列，L1/L2/L3 各一套配色 |
| G3 | 层级靠嵌套的圆角边框盒子表达 | 层级靠**内容列缩进**（12 / 32 / 52px）表达 |
| G4 | 展开箭头用 `<details>` 原生三角 | 箭头由 CSS 绘制，尺寸 6px；叶子节点用 4px 圆点 |
| G5 | 左右两栏比例失衡：左栏固定窄，右栏大片留白 | 左栏按树的宽度定，右栏自适应；两栏都要能被内容填满 |
| G6 | 搜索结果只显示节点名和层级 | 显示命中路径 `领域 › 分支 › 知识点`，让人知道它挂在哪 |
| G7 | 页面没有规模信息 | 标题区显示版本与节点数（`2026.09.7 · 382 个知识点`） |
| G8 | 没有「能不能当标签」的说明 | L1 只做统计，L2/L3 才是题目标签，界面上要能看出来 |

顺带发现（低优先级，可一并修）：`/favicon.ico` 返回 404，浏览器控制台有一条错误。

## 4. 页面目标形态

### 4.1 整体骨架

- 无顶栏，页面标题「知识树」在主体第一行，右侧放一行弱化的小字：`标签词表 2026.09.7 · 382 个知识点 · 342 个叶子`。
- 主体两栏：左栏树与检索，右栏知识点详情。
- 左栏建议 360–420px，内部独立滚动；右栏自适应，内部独立滚动。不要出现整页滚动条。
- 空数据状态：右栏未选中节点时，用一句说明加一个「随便看看」的引导（例如默认选中第一个 L1 的第一个分支），不要留一大片空白。

### 4.2 左栏

- 第一行：搜索框（输入即过滤，不需要按回车）。
- 第二行：层级筛选（全部 / 仅 L1 / 仅 L2 / 仅 L3）与「展开全部 / 折叠全部」。
- 树区：默认只展开 9 个 L1 领域行，L2/L3 折叠；点 L1/L2 展开收起。
- 搜索时切换为扁平命中列表，每条显示完整路径；清空关键词后回到树。
- 每行右侧固定等级框。L1 行整行深黑、白字；L2 行中灰、白字；L3 行浅灰、深字。这与模板 §5 一致。

### 4.3 右栏（知识点详情）

从上到下：

1. 面包屑路径：`基础算法 › 排序 › 快速排序`，每一段可点击跳转。
2. 名称（大字号）与 ID（等宽小字，弱化）。
3. 一句定位说明：`可作题目标签` 或 `只用于统计，不作为标签`。
4. 介绍正文：叶子知识点显示 `summary`；分支节点显示「该节点是分支，没有单独介绍」。
5. 下级节点列表（有下级时）：点击进入下级。
6. 详情只负责浏览知识树；操作入口后续按用户要求删除。

### 4.4 明确不做

- 不新增后端接口、不改数据库、不改标签内容。
- 不做题目数统计、不做标注入口、不做编辑词表（这些属于后续板块）。
- 不改侧栏、总览和其他页面的视觉。

## 5. 验收标准

1. 1440×900、1280×800 两种尺寸下，主体不出现纵向滚动条。
2. 1024px 宽度下不出现横向溢出。
3. 浏览器控制台无错误（favicon 404 一并修掉）。
4. 树的行高、圆角、配色、缩进、等级框与模板 §5 一致。
5. 搜索「最短路」能命中 2 条并显示完整路径；搜索「快速幂」能命中 `math.binary-exponentiation`。
6. 点击任意节点，右栏正确显示路径、介绍与下级。
7. 键盘可操作：Tab 能进入搜索框、筛选器、树节点，回车能触发。
8. `prefers-reduced-motion: reduce` 下取消位移，只保留透明度反馈。
9. `pytest -q` 全绿；全部前端模块 `node --check` 通过。
10. 更新 `docs/design/reference/knowledge-tree.png` 为新版截图。

## 8. 风险与注意

- 382 个节点一次性渲染是可行的，但不要给每个节点都加动画，入场动效只加在容器层。
- 搜索是前端过滤，不要每次输入都请求后端。
- 这一页不能出现「难度」「学习目标」「典型算法」等字段，它们已经被明确删除。
- 未提交改动很多，任何清理动作前先确认。
