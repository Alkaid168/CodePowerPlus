# 码力加加可用 MVP 设计

## 目标

构建一个单用户可直接使用的程序设计学习工作台：用户能够维护题库、分析题目、记录提交、查看知识点能力、获得推荐，并针对代码错误获取分级辅导。系统独立于学校 OJ，通过手工录入和公开数据启动。

## 产品结构

页面采用左侧导航和主内容区：题目库、题目分析、提交记录、能力画像、题目推荐、代码辅导。统一使用浅色背景、深蓝主色、青绿色成功色、橙色提醒色；卡片、表格、标签和状态徽章保持一致。移动端导航折叠为顶部菜单。

## 核心流程

题目库支持搜索、筛选、分页和详情；详情显示原题、分析标签、难度和解题思路。分析页支持标题、来源、题面录入，展示加载、成功、失败和重试状态。提交页要求题目、用户、语言、代码和评测结果，提交后可查看历史。画像页展示提交统计、AC 率、知识点掌握度和薄弱项。推荐页展示推荐题目、分数、推荐原因和目标知识点。辅导页展示代码、评测结果和逐级提示。

## 数据设计

题目包含标题、描述、来源、状态和创建时间；分析结果独立版本化，保存标签、难度、前置知识、思路、适合水平、置信度、模型和提示词版本。提交包含用户、题目、代码、语言、评测结果、标签和时间。辅导记录保存输入摘要、评测结果、模型回复和创建时间。

知识点使用独立的版本化树，层级参考 `docs/superpowers/specs/knowledge-taxonomy.md`。AI 只能返回知识点 ID，题目可关联多个节点并记录证据和置信度。

## 后端边界

Repository 只负责持久化；Service 负责模型调用、分析、画像、推荐和辅导；Router 负责 HTTP 校验与错误映射。所有外部模型响应经过 Pydantic 校验。SQLite 通过线程安全连接访问，数据库启动时执行幂等迁移。

## 可用性与安全

表单字段校验、题目不存在返回 404、模型未配置返回 503、模型失败不写入半成品。API Key 只来自环境变量。代码和题面不写入日志。前端显示明确错误、加载状态和重试入口。

## 验收标准

不配置模型时可完整使用题库、提交、画像和规则推荐；配置 DeepSeek 后可完成题目分析与代码辅导；通过浏览器完成一条完整学习流程；自动化测试覆盖数据层、服务层和 API；Docker 可启动服务。
